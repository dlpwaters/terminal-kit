# Upstream audit

This audit records the upstreams examined for Terminal Kit and the boundary between reusable terminal tooling and Omarchy's desktop distribution. Versions and commit IDs in [`../manifests/upstreams.json`](../manifests/upstreams.json) are the reproducibility record; links below are official project sources. The audit snapshot is 2026-09-30. Package repositories and release pages can move, so refresh the manifest deliberately when updating pins.

## Omarchy source boundary

The baseline is [Omarchy v4.0.4](https://github.com/omacom/omarchy/releases/tag/v4.0.4), commit `c668141e9c42b13c80c9ca4ea108e11708c5e8a5`. The release tree was inspected for `manual/`, `default/bash/`, `config/`, `install/omarchy-base.packages`, terminal configs, themes, helper scripts, package installation, and agent launchers. Omarchy is MIT licensed; the upstream notice is retained in [`../licenses/third-party/Omarchy-MIT.txt`](../licenses/third-party/Omarchy-MIT.txt). The adapted editor baseline retains Neovim's combined license and the LazyVim project/Starter Apache 2.0 notices. Two pinned portable plugins are added to the Omarchy-derived editor lock: SchemaStore.nvim commit `5553e77b8628b7a08fc2a5135c17647f11d828ee` and venv-selector.nvim commit `cc4bb3975de8835291f9bb45889e96c6b2795fc4`; all original baseline lock commits remain unchanged. Nerd Fonts' OFL 1.1 text is retained because the selected font archive is downloaded rather than vendored.

The Neovim package is maintained separately in [omacom-io/omarchy-pkgs](https://github.com/omacom-io/omarchy-pkgs), not in the Omarchy source repository. Omarchy's [file layout documentation](https://github.com/omacom/omarchy/blob/v4.0.4/docs/file-layout.md) identifies `omarchy-nvim` as an independent package that seeds `/etc/skel`; the v4.0.4 base package list names it but does not pin its recipe commit. We therefore record both the distro baseline and package source independently. The official stable [2026.8.13-1 package artifact](https://pkgs.omarchy.org/stable/x86_64/omarchy-nvim-2026.8.13-1-any.pkg.tar.zst) has SHA-256 `ff7cca4d58198ef6ea0c16ff93bd0369b307a40fae4ed300f6a2a75bb444fe1f`. Its `.BUILDINFO` PKGBUILD SHA-256 (`c91107a63b402fd58c1a614fe67e2d9c8f9fe5da2638233b3eccbbd126c4b106`) matches the recipe at commit `f20649b0a41ccc700e41d8a1d402b337a0f75cd4` in the package repository. The artifact's embedded `lazy-lock.json` SHA-256 is `f8693f2607088055adef508221e288b378a8df97411e0d726cbdb672d963a8ca`. The earlier June commit `78e5cc81953c44c804eb00e5be093e2674e09503` is version `2026.6.17-1`, not the source of this August package. The August recipe builds from [LazyVim Starter](https://github.com/LazyVim/starter) plus Omarchy-owned package files and checks the Starter `main` archive by SHA-256; the archive itself is not commit-pinned. Its PKGBUILD declares `neovim>=0.9.0` and `git` as runtime dependencies and `git`, Node.js, npm, and tree-sitter-cli as build dependencies; `.BUILDINFO` records build-time Neovim 0.12.4, Node.js 26.7.0, npm 12.0.2, tree-sitter-cli 0.26.9, and Git 2.55.0. Terminal Kit separately pins Neovim 0.12.5 for its profile. The PKGBUILD labels the aggregate package MIT, while the embedded Starter and LazyVim notices are Apache-2.0 and cached plugins carry their own notices. Do not represent the recipe as a source file inside the Omarchy v4.0.4 tag.

| Omarchy-only helpers and launchers | Omit | Do not copy Herdr (unverified for this kit), desktop skills/runtime, `omarchy-agent` task dispatch, or `opencode --auto`/approval-bypass aliases. |

The inspected Omarchy list and config also name GUI applications and hardware/system packages. They are outside Terminal Kit's terminal scope and are omitted rather than installed as incidental dependencies. Package-provider names vary by apt/dnf/pacman/Homebrew; the tool manifest is authoritative for those mappings and pinned user binaries.

## Installation portability

The user terminfo descriptions are fixed snapshots generated with `infocmp -x`: `tmux-256color` from ncurses 6.6-2 and `xterm-ghostty` from the official Arch Ghostty 1.3.1-arch2 package on the audit host. They live in `configs/terminfo/` and are compiled with the target host's `tic` into managed `~/.terminfo/` files. The ncurses and Ghostty MIT notices are retained under `licenses/third-party/`. This provides terminal capabilities over SSH without rewriting `TERM` or requiring root-owned terminfo changes.

Graphical Linux workstation installs select the native `wl-clipboard` or `xclip` package from the detected display protocol. macOS uses its built-in clipboard tools; Windows interop and SSH OSC 52 are selected by capability. Headless hosts do not install display packages, and clipboard commands time out rather than hanging on an unavailable session.

Intel macOS needs the explicit `intel-build` module with the current package ecosystem. Official Homebrew metadata lists tmux's libevent/ncurses/utf8proc/jemalloc dependencies and btop's lowdown/coreutils build prerequisites. The kit asks Homebrew for the transitive official-core dependency list, rejects unexpected names, and builds dependencies in topological order. Installed current dependencies are reused; only outdated dependencies in that graph are explicitly upgraded because current Homebrew source formulas require them. Separate per-formula operations avoid duplicate post-install actions. The complete native dependency phase has a 60-minute bound, and the full Intel setup can take 20–90 minutes. The kit disables automatic updates, install upgrades, dependent repairs and global cleanup using the [documented Homebrew environment controls](https://docs.brew.sh/Manpage), scoped to installer processes. The pinned Hermes `pyproject.toml` requires cryptography 50.0.0 for named security fixes; its [official PyPI distribution metadata](https://pypi.org/pypi/cryptography/50.0.0/json) supplies Apple Silicon wheels and no Intel macOS wheel. The opt-in uses isolated Rust 1.92.0 and native OpenSSL headers for that dependency; it does not downgrade cryptography or alter Hermes's lock/source.

Prefer a distribution's signed package repository for system dependencies. Prefer official project release artifacts or the project's documented installer for user-scoped tools, with explicit version/checksum records where the source supplies them. Never pipe an unpinned third-party installer into a privileged shell. Ghostty's official page distinguishes project binaries from distro and community packages; older Ubuntu/Debian releases may use a community package or build from source, but these remain an explicit user decision.

On macOS, the installer can bootstrap Homebrew using the official [`Homebrew/install` script](https://github.com/Homebrew/install/blob/f6632bc2e9afc0ba20cdee1f2d28bcd7672b3245/install.sh) pinned at commit `f6632bc2e9afc0ba20cdee1f2d28bcd7672b3245`; `scripts/bootstrap-homebrew.sh` verifies SHA-256 `fa4ed743b4ca38316c8f32fd6623baa5bbb928fd4a47ad9f49c2be78ea833449` before execution. Homebrew's official installer can require Command Line Tools or macOS authorization, so a noninteractive run may stop for a human prerequisite. `install.sh --dry-run` does not bootstrap it.

The three agent CLIs and configured LSP/formatter tools have been installed and version-checked on Debian 12; agent authentication remains the user's choice. Debian 12's glibc 2.36 cannot run the pinned upstream Tree-sitter CLI binary builds that require glibc 2.39. The explicit `treesitter-build` option compiles pinned source version 0.26.1 (commit `8a3dcc6155a9faae677544303b6bc0caf1aef296`, archive SHA-256 `ca739fcb6fdb9cf2312d687332282040f088ea5c517a65ea98f980a861babc27`) with isolated Rust 1.92.0. It uses locked Cargo dependencies, two build jobs, and the native libclang development package; no system libraries are updated. Ghostty and font physical-host acceptance remain separate checks; see [support status](SUPPORT.md). Windows WSL relies on a Windows-host terminal and font install step, because Ghostty has no native Windows app.
